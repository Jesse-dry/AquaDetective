## 4. 数据层设计

### 4.1 SQLite Schema（核心表）

```sql
-- 流域节点（河流分段/源头/汇合口/出口）
CREATE TABLE nodes (
  id TEXT PRIMARY KEY,          -- 如 'n_01'
  name TEXT NOT NULL,
  kind TEXT NOT NULL,           -- source|segment|confluence|outlet
  x REAL, y REAL,               -- 地图坐标（与前端底图约定坐标系）
  flow REAL NOT NULL,           -- 流量 m³/s
  velocity REAL NOT NULL,       -- 流速 m/s
  k REAL NOT NULL DEFAULT 0.1   -- 降解系数 1/d
);

-- 有向边（下游方向）
CREATE TABLE edges (
  from_node TEXT NOT NULL REFERENCES nodes(id),
  to_node   TEXT NOT NULL REFERENCES nodes(id),
  distance_m REAL NOT NULL,
  PRIMARY KEY (from_node, to_node)
);

-- 监测断面（自动监测站）
CREATE TABLE stations (
  id TEXT PRIMARY KEY,          -- 如 'st_03'
  node_id TEXT NOT NULL REFERENCES nodes(id),
  interval_min INTEGER DEFAULT 15,
  indicators TEXT NOT NULL      -- JSON: 监测指标列表
);

-- 企业/污染源
CREATE TABLE enterprises (
  id TEXT PRIMARY KEY,          -- 如 'ent_07'
  name TEXT NOT NULL,
  industry TEXT NOT NULL,       -- electroplating|dyeing|paper|chemical|pharma|food|wwtp
  node_id TEXT NOT NULL REFERENCES nodes(id),   -- 排污口所在节点
  discharge_pattern TEXT NOT NULL -- JSON: {day_night:[..], hours:[..], season:[..]}
);

-- 水质指纹（双指纹：光谱 + 特征污染物）
CREATE TABLE fingerprints (
  enterprise_id TEXT PRIMARY KEY REFERENCES enterprises(id),
  spectrum TEXT NOT NULL,       -- JSON: [{lex,lem,amp,sigma}...] 荧光峰参数
  pollutants TEXT NOT NULL      -- JSON: {氨氮:0.8, Cr6+:0.05, ...} 归一化比例向量
);

-- 时序数据（宽表一张，指标一列；数据量演示级足够）
CREATE TABLE readings (
  station_id TEXT NOT NULL REFERENCES stations(id),
  ts INTEGER NOT NULL,          -- epoch 秒
  indicator TEXT NOT NULL,      -- cod|ammonia|tp|cr6|ph|...
  value REAL NOT NULL,
  PRIMARY KEY (station_id, ts, indicator)
);

-- 污染事件（含 Ground Truth，演示/验证用）
CREATE TABLE events (
  id TEXT PRIMARY KEY,
  station_id TEXT NOT NULL,
  indicators TEXT NOT NULL,
  onset_ts INTEGER NOT NULL,
  severity TEXT NOT NULL,       -- low|medium|high
  etype TEXT NOT NULL,          -- sudden|periodic|gradual
  truth_source TEXT,            -- Ground Truth 企业 id（演示脚本用）
  status TEXT DEFAULT 'open'    -- open|investigating|resolved
);

-- 事件发生时的独立观测。调查引擎只读取本表，不能读取 truth_source 生成证据
CREATE TABLE event_observations (
  event_id TEXT PRIMARY KEY REFERENCES events(id),
  station_id TEXT NOT NULL,
  eem TEXT NOT NULL,             -- JSON: {lex, lem, eem}，不含来源标签
  pollutants TEXT NOT NULL       -- JSON: 现场特征污染物比例向量
);

-- 溯源结论（每次调查一条）
CREATE TABLE investigations (
  id TEXT PRIMARY KEY,
  event_id TEXT NOT NULL REFERENCES events(id),
  started_at INTEGER NOT NULL,
  conclusion TEXT,              -- JSON: {source_id, confidence, evidence:[...]}
  status TEXT DEFAULT 'running' -- running|resolved|failed
);
```

### 4.2 时序生成器（`series_generator.py`）

- 输入：流域配置 + seed（**必须支持 seed 复现**，演示可一键重置）
- 正常基线：`值 = 季节因子 × 昼夜因子 × 基准浓度 × (1 + 噪声)`，噪声按指标配置 CV
- 事件注入（三类，对应三条演示脚本）：
  - `sudden`：阶跃 + 指数衰减（突发泄漏），作用于泄漏源下游各断面，浓度按扩散模型衰减
  - `periodic`：夜间 22:00~03:00 周期性抬升（偷排）
  - `gradual`：缓慢爬升 + 周波动（面源/生活污水）
- 输出：写入 `readings`、`events` 和独立的 `event_observations`；`truth_source` 仅供离线评测
- 约定：一个"世界"= 连续 90 天、15 分钟间隔 ≈ 8640 条/断面/指标，12 断面 × 5 指标 ≈ 52 万行，SQLite 无压力

### 4.3 指纹库（`fingerprint_lib.py`）

- 光谱指纹：每个企业 2~4 个荧光峰 `{lex, lem, amp, sigma}`，可合成 EEM 矩阵（lex 200~500nm，lem 250~600nm，网格化 61×71）
- 污染物指纹：5~8 维归一化比例向量，按行业模板生成（电镀重 Cr⁶⁺/Ni、印染重色度/苯胺、制药高 TOC）
- 提供：`synthesize_eem(fingerprint) -> np.ndarray`、`save/load`
- 行业模板放 `data/industry_profiles.json`，便于调参

## 6. Agent 层（LangGraph 多智能体）

### 6.1 状态定义（`state.py`）

```python
class InvestigationState(TypedDict):
    event: dict                    # 事件详情
    hypotheses: list[dict]         # [{id, target_id, reasons, evidence, score, status}]
    evidence_log: list[dict]       # [{step_id, phase, clue, reasoning, evidence}]
    conclusion: dict | None        # {source_id, confidence, evidence_summary}
    report: str | None             # Markdown
    stream: list[dict]             # 待推送消息队列（WS 消费）
```

### 6.2 状态机（`graph.py`，侦探式核心流程）

```
monitor(常驻轮询)
  └─ 发现异常 → build_event → 通知 investigate
investigate 子图:
  parse_event ─→ generate_hypotheses(LLM, 3~5 个)
      └→ verify_loop(工具循环, 最多 N 轮):
            topology_filter → dispersion_check → fingerprint_match
            → pattern_check → 更新每个假设 score/evidence
      └→ conclude: 最高分 > 阈值 → resolved；否则 failed(建议增测)
  └─ 按需唤醒 compliance(法规 RAG) / responder(处置建议) / reporter(报告)
```

关键设计：
- **Supervisor 模式**：investigator 是主编排，动态唤醒其他 Agent；"Agent 会议"环节（溯源 vs 法规争论适用标准）作为演示亮点，真实实现为一次多角色 LLM 调用，双方观点写入 evidence_log
- **verify_loop 每步产出"线索→推理→证据"三元组**，推入 `state["stream"]`，由 WS 转发前端——这是 demo 的灵魂
- **LLM 只做**：假设生成、证据的自然语言化、排除理由表述；**一切数值来自 engine 工具**
- 工具白名单（`tools.py`）：`query_station_series` / `trace_upstream` / `simulate_spill` / `match_eem` / `match_pollutants` / `analyze_periodicity` / `search_regulations`(RAG) / `get_enterprise_profile`

### 6.3 推理落盘（`recorder.py`）

- 每次调查完整写入 `data/recordings/{investigation_id}.jsonl`（含 stream 全部消息 + 最终报告）
- 提供 `replay(investigation_id) -> list[dict]`，前端可做"回放模式"，答辩利器

### 6.4 LLM 封装（`llm.py`）

- OpenAI 兼容：`base_url` / `api_key` / `model` 全部走环境变量（`.env.example` 注释清楚）
- 超时 + 失败降级：LLM 挂了时用规则模板生成假设（保证演示不因网络挂掉）
- 所有 LLM 调用带 `temperature=0.2`，输出要求 JSON Schema 校验（`response_format` 或 prompt + pydantic 校验，失败重试 1 次）

## 7. API 契约（后端交付给前端）

Base URL：`http://localhost:8000/api/v1`（CORS 全开，演示期）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/watershed` | 全流域拓扑：nodes/edges/stations/enterprises（一次拉全，前端画图） |
| GET | `/watershed/enterprises/{id}/fingerprint` | 企业指纹（光谱参数 + 污染物向量） |

| POST | `/events/{id}/investigate` | 触发溯源调查，返回 investigation_id |
| GET | `/investigations/{id}` | 调查状态与当前结论 |
| GET | `/investigations/{id}/report` | Markdown 报告 |
| POST | `/simulate/reset?seed=` | 重置世界（重跑数据引擎，演示一键复位） |

## 11. 风险与对策（后端相关）

| 风险 | 对策 |
|---|---|
| LLM 现场无网/欠费 | `llm.py` 降级模板；`.env` 支持指向本地模型（如 Ollama） |
| LangGraph 版本 API 变动 | 锁定版本号入 `pyproject.toml`（如 `langgraph>=0.2,<0.3`），W2 第一天先跑官方示例 |
| 生成数据量过大导致查询慢 | 查询默认降采样；索引 `(station_id, ts)`；必要时 Parquet 预计算 |
| 数值不稳定（扩散求解发散） | CFL 条件校验：`dt <= dx/velocity`，不满足时自动加密 |
| 演示时想现场造新事件 | `/simulate/inject` 支持运行时注入，无需重建库 |
