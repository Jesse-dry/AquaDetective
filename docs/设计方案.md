# 水质预警溯源智能体（AquaDetective）设计方案

> 智理杯 vibe-coding 赛道 · 方向：A 侦探式溯源推理 + B 多智能体指挥中心 + C 水质指纹溯源
> 技术路线：自研 Agent 编排（Python + LangGraph），模拟数据为主 + 真实公开数据对标验证

---

## 1. 项目定位

**一句话卖点**：一个"水域侦探"——从水质异常预警到污染源锁定再到处置报告，全程由多智能体自动推理完成，每一步推理过程可视化、可解释、有依据。

**对标真实技术**（用于增强可信度与答辩背书）：
- 清华苏州环境创新研究院的水质指纹预警溯源技术已在多地落地：台州椒江建立浙江首个企业端"水质指纹"溯源数据库、长治市引入清华技术让"隐形污染显形"、黄河乌海段 24 小时预警溯源系统上线、宁波实现"水质指纹"最快 21 分钟溯源。
- 核心原理：不同行业废水具有特征性三维荧光光谱（EEM）"指纹"，通过指纹库比对可锁定污染源企业。

**差异化**：不只是一个聊天机器人，而是"确定性计算引擎 + LLM 推理编排 + 可视化大屏"三合一的产品。

---

## 2. 系统架构（四层）

```
┌─────────────────────────────────────────────────┐
│  展示层  Web 大屏：流域地图 / 推理过程流式展示 /     │
│          浓度动画 / 指纹比对可视化 / 报告导出        │
├─────────────────────────────────────────────────┤
│  Agent 层  LangGraph 多智能体编排                  │
│   监测Agent → 溯源Agent(侦探主编排) → 法规Agent     │
│   → 处置Agent → 报告Agent（Supervisor 模式）       │
├─────────────────────────────────────────────────┤
│  计算层  确定性引擎（LLM 不可触碰，防幻觉）          │
│   异常检测 / 对流扩散模拟 / 指纹匹配 / 拓扑溯源       │
├─────────────────────────────────────────────────┤
│  数据层  模拟数据引擎（流域 + 企业 + 事件注入）       │
│          公开数据对标集（真实案例验证）              │
└─────────────────────────────────────────────────┘
```

**铁律**：所有数值计算（超标判断、扩散浓度、指纹相似度、上下游关系）全部走确定性代码，LLM 只负责推理编排、假设生成、自然语言表达。这是答辩时防"幻觉"攻击的护城河。

## 3. 数据层设计（模拟为主，真实对标）

### 3.1 流域模型（以真实流域为蓝本简化）

以钱塘江/太湖流域某段为蓝本，构建简化流域图（NetworkX 有向图）：

| 元素 | 数量 | 说明 |
|---|---|---|
| 河流分段节点 | 30~50 | 含干流、支流、汇合点 |
| 监测断面 | 8~12 | 自动监测站，每 15 分钟一条记录 |
| 企业/污染源 | 15~20 | 分行业：电镀、印染、造纸、化工、制药、食品、污水处理厂 |
| 排污口 | 每企业 1~2 | 挂在流域图上，有排放规律 |
| 水文参数 | — | 各段流量、流速、降解系数 k |

### 3.2 水质指纹库（核心创新点）

每个企业定义**双指纹**，模拟真实 EEM 荧光光谱技术：

1. **光谱指纹**：每个污染源定义 2~4 个荧光峰（激发波长 λex、发射波长 λem、强度、半峰宽），可合成 EEM 矩阵；匹配用余弦相似度 + 皮尔逊相关，相似度 > 0.85 判定"高度吻合"。
2. **特征污染物指纹**：特征污染物组合及比例向量（如电镀：Cr⁶⁺、Ni、CN⁻、pH 低；印染：色度、苯胺类、高 COD；制药：抗生素残留、高 TOC）。

可视化：EEM 等高线图（荧光图谱）对比展示——"案发现场指纹 vs 企业档案指纹"，视觉冲击力强，评委容易理解。

### 3.3 时序数据生成引擎

- 正常基线：季节趋势 + 昼夜波动 + 随机噪声（按指标配置 CV）
- 事件注入：三类事件（对应三条演示脚本）
  - **突发泄漏**：浓度阶跃式突变 + 指数衰减
  - **夜间偷排**：特定时段（22:00~03:00）周期性抬升
  - **渐变恶化**：缓慢爬升（面源/生活污水），短期难察觉
- 每次生成记录 Ground Truth（真实事件源），供验证与演示

### 3.4 真实数据对标

- 内置 2~3 个公开真实数据集（地表水国控断面月报等），跑异常检测算法验证"算法在真实数据上同样有效"
- 演示末尾放一页"真实案例对标"：椒江、长治、黄河乌海、宁波的公开报道，说明我们方案与真实行业技术同源
- 声明：演示流域为模拟数据（避免数据真实性被攻击），真实数据仅用于算法验证

## 4. 计算层（确定性引擎）

| 模块 | 方法 | 输出 |
|---|---|---|
| 异常检测 | 3σ + CUSUM + EWMA + 季节基线对比 | 异常事件（时间、断面、指标、程度、突变/渐变分类） |
| 对流扩散模拟 | 一维对流-扩散方程显式差分求解 | 下游各断面浓度随时间变化（供动画） |
| 指纹匹配 | EEM 余弦相似度 + 特征污染物比例比对 | 嫌疑企业排序 + 置信度 |
| 拓扑溯源 | 流域图上溯可达性 + 流速×时间窗反推距离 | 嫌疑源候选集合（缩小到 3~5 个） |
| 排放规律分析 | 时序相关性：偷排时段 vs 企业排水规律 | 时间维度佐证 |

## 5. Agent 层设计（LangGraph 多智能体）

### 5.1 智能体分工

| Agent | 职责 | 工具 |
|---|---|---|
| 监测 Agent（常驻） | 轮询数据、异常检测、事件分级预警 | 异常检测工具、断面查询 |
| 溯源 Agent（侦探，主编排） | 收到预警后展开推理：假设→验证→排除→锁定 | 拓扑、扩散、指纹、排放规律工具 |
| 法规 Agent | RAG 检索标准与法条 | GB 3838-2002、HJ 系列、水污染防治法、应急预案模板 |
| 处置 Agent | 根据事故类型生成调度与处置建议 | 预案模板库、泄漏处置知识 |
| 报告 Agent | 汇总全链路生成结构化报告 | 报告模板、时间线数据 |

### 5.2 侦探式推理状态机（核心体验）

```
事件触发(监测Agent)
  → ① 事件解析：超标指标/幅度/位置/时间
  → ② 假设生成(LLM)：结合水文、时段、行业分布提出 3~5 个假设
  → ③ 假设验证(工具循环)：
       拓扑过滤(谁在上游、时间窗内可能到达)
       → 扩散反推(浓度幅度与源强是否匹配)
       → 指纹比对(光谱+污染物双指纹打分)
       → 排放规律(偷排时段与企业规律相关性)
  → ④ 排除/确认：每个假设给"证据 + 置信度"，排除低分假设
  → ⑤ 结论：锁定嫌疑源（或上报"无法锁定+建议增测"）
  → ⑥ 处置建议(处置Agent) + 报告生成(报告Agent)
```

**每一步的"线索 → 推理 → 证据"三元组都流式推到前端展示**——这是 demo 的灵魂，侦探叙事感全靠它。

### 5.3 多智能体协作亮点

- Supervisor 模式：溯源 Agent 为主，可动态唤醒法规/处置/报告 Agent
- 展示"Agent 会议"：溯源 Agent 与法规 Agent 就"超标限值适用标准"交换意见（真实能力，演示效果好）
- 全部推理过程落盘为 JSONL，可回放（答辩神器）

## 7. 演示故事线（三条预置脚本）

1. **场景一 · 夜间偷排**（电镀厂）：经典指纹溯源全流程，侦探推理 5 步锁定，约 3 分钟
2. **场景二 · 突发泄漏**（化工园区）：扩散动画 + 快速预警 + 应急调度建议，视觉冲击最强
3. **场景三 · 渐变恶化**（生活污水/面源）：CUSUM 长周期检出 + 图谱分析，展示技术深度

每条脚本可一键重置、可注入随机扰动（体现"不是录屏"）。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| LLM 幻觉（编数据/编法规） | 计算全走确定性工具；法规 Agent 只允许 RAG 检索结果 |
| 评委质疑数据真实性 | 明确标注"模拟数据 + 真实算法验证"，附真实案例对标页 |
| 演示现场翻车 | 3 条预置脚本 + 手动事件注入 + 数据可重置 + 本地 LLM 降级 |
| 溯源结果错误 | 指纹匹配不到高分时如实报告"无法锁定 + 建议增测点位"（反而体现严谨） |
| 工作量过大 | 指纹模拟用参数化合成，不追求物理级精度；前端用现成组件库 |

## 11. 答辩话术要点

- **为什么是 Agent 而不是传统系统**：传统预警系统只能报警，我们的 Agent 能"侦查"——假设-验证循环、多源证据融合、自动生成报告
- **为什么可信**：确定性引擎兜底 + 推理过程全透明 + 对标真实落地技术
- **vibe-coding 体现**：LLM 辅助下 6 周完成"数据→算法→Agent→产品"全链路
