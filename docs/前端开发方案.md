# AquaDetective 前端开发方案

> 对应总方案 `docs/设计方案.md` 与 `docs/后端开发方案.md`,本文档只聚焦前端,包含:职责边界、
> 技术栈、页面与组件设计、状态管理、API/WS 对接、Mock 策略、测试策略、里程碑与验收标准。
> 前端只消费后端 API,不做任何数值计算,所有"线索/推理/证据"均来自后端 WS 推送。

---

## 1. 职责边界

| 模块 | 归属 | 说明 |
|---|---|---|
| 流域地图渲染(节点/边/断面/企业) | 前端 | 消费 `/watershed`,MapLibre 一次拉全 |
| 推理过程流式面板(打字机 + 证据卡片) | 前端 | 消费 WS 消息,只渲染不加工 |
| 浓度动画(扩散热力条) | 前端 | 消费扩散模拟时序数据 |
| 指纹比对可视化(EEM 等高线图) | 前端 | 消费 `/stations/{id}/eem` 与企业指纹 |
| 时序图表(断面指标曲线) | 前端 | 消费 `/series`,ECharts |
| 报告展示与 PDF 导出 | 前端 | 后端出 Markdown,前端渲染 + 转 PDF |
| 大屏模式 / 事件注入按钮 / 一键重置 | 前端 | 调 `/simulate/*`,演示保险 |
| 一切数值计算与推理 | 后端 | 前端零计算,防"前端改数"质疑 |

**铁律**:前端是"纯粹的展示与交互层"。超标判断、置信度、相似度等数字全部原样渲染后端返回值,不做二次加工(除格式化,如保留两位小数)。

## 2. 技术栈

| 用途 | 选型 | 说明 |
|---|---|---|
| 框架 | React 18 + TypeScript + Vite | 类型安全对接 API 契约 |
| 地图 | MapLibre GL JS | 流域图、断面着色、扩散动画图层 |
| 图表 | ECharts | 时序曲线、EEM 等高线图(heatmap)、置信度条形图 |
| 样式 | Tailwind CSS | 大屏深色科技风,快速出效果 |
| 状态 | Zustand | 轻量,适合 WS 消息驱动的高频更新 |
| 路由 | React Router | 大屏页 / 调查页 / 报告页 / 对标页 |
| HTTP | fetch 封装 + 自动重试 | 演示环境,不引入复杂库 |
| WS | 原生 WebSocket + 自动重连 | 断线重连是演示刚需 |
| PDF | `window.print()` 打印为 PDF | 零依赖,报告页配打印样式即可 |
| 包管理 | pnpm | 与后端 uv/poetry 互不干扰 |

## 4. 页面设计

### 4.1 大屏主页 `DashboardPage`(演示主战场)

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏:Logo / 世界时钟(模拟时间) / 场景脚本按钮 / 重置按钮    │
├───────────────┬──────────────────────┬───────────────────┤
│ 告警面板        │      流域地图          │   推理面板           │
│ (事件列表,     │  (MapLibre,断面着色,  │  (流式步骤卡片,      │
│  点击触发调查)  │   扩散动画图层)       │   假设榜,Agent对话)  │
├───────────────┴──────────────────────┴───────────────────┤
│ 底部:选中断面时序曲线(可切换指标)                            │
└──────────────────────────────────────────────────────────┘
```

- **左栏告警面板**:`GET /events?status=open`,新事件到达时红条闪烁 + 提示音(可关);点击"开始侦查"→ `POST /events/{id}/investigate`
- **中栏地图**:断面圆点按最新状态着色(绿正常/黄预警/红超标);触发泄漏场景时扩散动画沿河道向下游流动;企业图标在溯源锁定后高亮闪烁
- **右栏推理面板**:demo 的灵魂,详见 4.2
- **底栏曲线**:点击地图断面后展示该断面时序,异常时段以红色背景区间标注

### 4.2 推理面板 `ReasoningPanel`(核心组件)

逐条渲染 WS 消息,严格按契约:

| WS type | 渲染形式 |
|---|---|
| `step` | 步骤卡片:phase 标签(拓扑过滤/扩散反推/指纹比对/规律分析) + 线索 + 打字机效果推理文本 + 证据条列表 |
| `hypothesis` | 假设榜:企业名 + 分数进度条,分数变化带过渡动画,被淘汰假设变灰划线 |
| `agent_talk` | 气泡对话(不同 Agent 不同颜色头像),"Agent 会议"即多条交替气泡 |
| `conclusion` | 全宽高亮卡片:锁定企业 + 置信度 + 地图联动高亮该企业 |
| `failed` | 黄色严谨性卡片:无法锁定原因 + 增测建议(答辩加分项) |
| `report_ready` | 卡片内"查看报告"按钮 → 跳报告页 |

打字机效果用 CSS/定时器实现,**文本完整到达后才开始打字**,避免与流式 token 耦合;速度可调,提供"跳过动画"按钮(评委赶时间时直接全量展示)。

### 4.3 断面详情页 `StationPage`

- 多指标时序曲线(ECharts,可缩放),异常点打标
- EEM 等高线图(`EemContour`,heatmap 61×71):左侧"现场指纹",右侧下拉切换企业档案指纹并排对比,下方显示相似度分数条

### 4.4 报告页 `ReportPage`

- `GET /investigations/{id}/report` 拉 Markdown → `react-markdown` 渲染
- 报告结构:事件摘要 / 时间线 / 推理证据链(嵌步骤卡片只读版) / 法规引用 / 处置建议
- "导出 PDF"按钮 = `window.print()` + 专用 `@media print` 样式(隐藏导航,白底)

### 4.5 回放页 `ReplayPage`

- `GET /recordings` 列表 → 选择一次历史调查 → 按 JSONL 时间序逐条重放到推理面板
- 用途:答辩现场网络/LLM 全挂时的终极兜底,以及赛后复盘

### 4.6 对标页 `BenchmarkPage`(W5)

- 真实公开数据集的异常检测结果图表 + 椒江/长治/黄河乌海/宁波案例图文
- 页首醒目声明:"演示流域为模拟数据,真实数据仅用于算法验证"

## 5. 状态管理与数据流

```
WS 消息 ─→ connection.ts ─→ investigationStore ─→ ReasoningPanel/HypothesisBoard
                                        └───────→ map 高亮联动
REST ─→ api/* ─→ watershedStore(拓扑,会话级缓存)
             └→ alertStore(事件列表,30s 轮询 + 调查后刷新)
UI 状态(选中断面/大屏模式/场景脚本)─→ uiStore
```

约定:
- `investigationStore` 以 `step_id` 去重,保证 WS 重连重放不产生重复卡片
- WS 断线:自动重连(指数退避,最多 5 次),重连后调 `GET /investigations/{id}` 补齐当前状态,面板顶部显示连接状态灯
- 同一时间只允许一个活跃调查(与后端约定),新调查开始前清空 `investigationStore`

## 6. 与后端的契约对接

Base:`/api/v1`,开发期 Vite proxy 到 `http://localhost:8000`。

| 前端消费点 | 接口 | 备注 |
|---|---|---|
| 地图初始化 | `GET /watershed` | 进入大屏拉一次,存 `watershedStore` |
| 告警面板 | `GET /events?status=` | 轮询 30s |
| 触发调查 | `POST /events/{id}/investigate` | 返回 id 后立即建立 WS |
| 推理流 | `WS /ws?investigation_id=` | 消息类型见后端方案 7.1 |
| 结论兜底 | `GET /investigations/{id}` | WS 断线重连后补齐 |
| 报告 | `GET /investigations/{id}/report` | Markdown |
| 断面曲线 | `GET /series?...` | 大图默认带 `step` 降采样 |
| EEM 对比 | `GET /stations/{id}/eem` + `GET /watershed/enterprises/{id}/fingerprint` | 指纹参数前端合成矩阵只做展示 |
| 演示控制 | `POST /simulate/reset` / `POST /simulate/inject` | ScenarioBar / InjectDialog |
| 回放 | `GET /recordings` / `GET /recordings/{id}` | ReplayPage |

**契约类型同步**:`src/types/` 依据 `docs/API契约.md` 手写 TS 接口,W1 末契约冻结后改动需双方确认;WS 消息用 discriminated union(`type` 字段)建模,switch 渲染,新增类型时编译器强制补分支。

## 7. Mock 策略(契约冻结前并行开发)

- `public/mock/` 内置全套静态数据 + 一份完整推理流样例(按契约逐条消息)
- `VITE_MOCK=1` 时:`api/*` 读静态 JSON;`mockStream.ts` 按时间间隔逐条推送样例消息,完整模拟一次"夜间偷排"调查
- 收益:前端 W1~W2 不依赖后端进度即可把推理面板、假设榜、地图动画全部做完;后端联调时只需关开关
- 演示兜底:现场后端异常时,ScenarioBar 提供"离线演示模式"开关,全程走 mock(写明仅限兜底,正常演示走真实链路)

## 8. 测试策略

| 层 | 方式 |
|---|---|
| 纯函数/组件 | Vitest + React Testing Library:StepCard 渲染各 type 消息、HypothesisBoard 排序与淘汰态、store 去重逻辑 |
| 契约守卫 | mock 数据与 `docs/API契约.md` 字段人工对齐清单;TS 类型即编译期守卫 |

| 演示彩排 | 每条脚本至少完整跑 3 遍,含一次断网降级与一次回放兜底 |

## 9. 里程碑与验收标准(前端视角,对齐总方案 W4~W5)

| 周 | 交付 | 验收标准 |

| W2 | 推理面板 + 告警面板 + 假设榜 | mock 流驱动下完整呈现一次调查全过程(步骤卡片/打字机/假设榜/Agent 对话/结论卡) |

## 10. 风险与对策(前端相关)

| 风险 | 对策 |
|---|---|
| 契约未冻结导致返工 | W1 末推动契约冻结;此前只依赖 mock,组件与数据层严格分离 |
| WS 现场断连 | 自动重连 + REST 补齐 + 连接状态灯;极端情况切回放页兜底 |
| 动画/图表性能(大屏高分屏) | ECharts 开启 `sampling`;扩散动画用 MapLibre 自定义图层批量更新,避免逐帧 React setState |
| 打字机与高频消息冲突 | 消息先入 store 再动画,动画只影响展示不影响数据;"跳过动画"按钮 |
| PDF 样式翻车 | 提前做 `@media print` 样式并用真实报告试打印;备选方案为直接展示 Markdown 页面 |
| 评委质疑前端美化数据 | 面板角落标注数据来源接口;所有数字原样渲染后端值,答辩话术明确"前端零计算" |
| 演示时间不可控 | 推理流速可调 + 跳过动画;场景脚本时长预演并写入话术 |

## 11. 与后端的分工约定(前端确认版)

1. `docs/API契约.md` W1 末冻结,含 WS 全部消息类型与字段;变更需双方确认并同步改 TS 类型
2. 坐标系:节点 `(x, y)` 以契约约定为准(经纬度或 Web Mercator),W1 第一周与后端各画一个点验证对齐
3. 时间戳:后端统一毫秒 epoch,前端只做格式化展示
4. 报告:后端只出 Markdown,PDF 由前端打印方案承担,后端不引入 PDF 依赖
5. 联调窗口:W3 末预留 2 天集中联调,联调前后端保证 `seed.py` 一键建库 + 场景一脚本可手动触发
