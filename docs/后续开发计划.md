# AquaDetective 后续开发计划

> 版本：v1.0  
> 制定日期：2026-08-20  
> 适用目标：3-4 人团队在 4 周内完成可信、可复现、可演示的 MVP

## 1. 项目目标

本阶段交付一套从公开水质数据进入系统，到异常预警、污染溯源、证据展示和报告生成的完整流程：

```text
公开数据/模拟数据
  -> 数据标准化与质量检查
  -> 异常检测和事件融合
  -> 上游候选污染源筛选
  -> 传播、指纹、排放规律等证据评分
  -> Agent 调查编排
  -> 地图、证据链和调查报告
```

MVP 必须满足：

1. 模拟流域三类事件可以稳定演示。
2. 至少接入一个公开真实水质数据集。
3. 在真实背景或真实河网上完成隐藏真值的溯源评测。
4. 调查引擎不能读取 `truth_source` 等评测标签。
5. LLM 不可用时仍能完成确定性调查流程。
6. 新环境可以按照文档复现安装、测试和启动。

本阶段不承诺生产级实时接入、行政执法结论、大规模并发或真实企业级 EEM 指纹库。

## 2. 数据路线

采用“中国主场景 + 美国公开基准 + 模拟事件”的组合路线。

具体数据入口、筛选标准和登记模板见[公开数据获取指南](公开数据获取指南.md)。

### 2.1 中国主场景

用途：体现本地业务价值，验证真实水质趋势和异常检测。

优先寻找：

- 国家或地方地表水自动监测数据；
- 生态环境部地表水水质月报；
- 省市政府开放平台中的断面水质数据；
- 排污许可证公开信息和重点排污单位名录；
- 可获得的降雨、流量、水位数据；
- HydroRIVERS、MERIT Hydro 或 OpenStreetMap 河网。

选择数据时必须确认：时间跨度、采样频率、断面坐标、指标单位、质量标志、许可和可重复下载方式。

### 2.2 美国公开基准

用途：建立公开、可复现、可关联的端到端溯源基准。

计划组合：

- EPA Water Quality Portal：水质观测；
- USGS Water Data：流量和水位；
- EPA ECHO/DMR：企业、排口、许可证和排放记录；
- NHDPlus：河网拓扑和汇水区。

美国数据用于验证算法和数据架构，不直接用于确定中国场景的法规结论或最终评分权重。

### 2.3 模拟数据

用途：稳定演示、边界测试和隐藏真值评测。模拟数据必须明确标识，生成器可访问真值，但调查引擎只能访问生成后的观测数据。

## 3. 数据规范

原始文件不得覆盖，目录约定如下：

```text
data/raw/          原始下载快照
data/interim/      清洗和映射中的中间结果
data/processed/    标准化 Parquet/CSV
metadata/          数据来源、许可、字段和下载时间
```

标准观测记录至少包含：

| 字段 | 说明 |
|---|---|
| `dataset_id` | 数据集标识 |
| `station_id` | 统一断面标识 |
| `timestamp_utc` | UTC 时间 |
| `parameter_code` | 统一指标编码 |
| `value` / `unit` | 数值和标准单位 |
| `qc_flag` | 原始或系统质量标志 |
| `detection_limit` | 检出限，可为空 |
| `lat` / `lon` | WGS84 坐标 |
| `source_url` | 数据出处 |
| `retrieved_at` | 获取时间 |

必须单独映射 COD、CODMn、TOC、氨氮、总氮等不同概念，不得仅按名称近似合并。

## 4. 工作分解

### P0：可信和可复现基线

- 隔离模拟观测与 `truth_source`；
- 增加事件观测表和回归测试；
- 锁定 Python 依赖并提供统一安装方式；
- 建立 CI，运行单元测试和 API 集成测试；
- 修复重复调查、失败恢复和 WebSocket 重连等基础问题。

### P1：公开数据接入

- 定义统一站点、观测、河段、污染源和水文数据模型；
- 先实现一个中国数据导入器；
- 实现一个美国流域离线样例导入器；
- 保存原始快照、字段映射和数据许可元数据；
- 输出数据质量报告。

### P1：预警与溯源算法

- 接通监测 Agent 的定时扫描；
- 合并同一断面的多指标异常，避免重复事件；
- 增加季节基线、缺失值和传感器异常处理；
- 用到达时间、流量和浓度曲线进行传播校核；
- 提供未知污染源选项和置信度分解；
- 禁止 LLM 生成或修改数值证据。

### P1：前端工作台

- 流域地图和断面状态；
- 告警列表与水质时序；
- 调查时间轴和候选源排名；
- EEM/污染物指纹对比；
- 证据来源、置信度和不确定性；
- 报告查看、历史调查回放和失败状态。

### P2：法规、部署与答辩

- 法规文档版本化、分块检索和引用；
- 鉴权、审计、日志和基础监控；
- 演示部署、一键重置、备用录屏；
- 架构图、数据说明、评测结果和失败案例说明。

## 5. 四周里程碑

| 时间 | 主要任务 | 验收标准 |
|---|---|---|
| 第 1 周 | P0 基线、真值隔离、监测调度、自动测试 | 三类模拟事件可自动预警并完成调查，测试可复现 |
| 第 2 周 | 中国数据导入、统一模型、真实河网样例 | 一条命令生成标准化数据和质量报告 |
| 第 3 周 | 溯源评分、公开基准、前端主流程 | 前后端端到端跑通，能够显示证据和未知来源 |
| 第 4 周 | 评测、法规引用、部署和演示打磨 | 一键演示，评测报告和备用录屏齐全 |

## 6. 人员分工建议

| 角色 | 主要责任 |
|---|---|
| 数据/后端 | 数据适配器、数据库、API、任务调度、部署 |
| 算法 | 异常检测、河网溯源、证据评分、评测 |
| 前端 | 地图、时序图、调查过程、报告与回放 |
| 产品/Agent | 工作流、法规资料、测试、文档和演示总控 |

三人团队可由数据/后端同时承担产品和 Agent 工作，算法负责人承担数据评测。

## 7. 环境和资源

- Python 3.11、`uv`、FastAPI、LangGraph；
- Node.js 20、React、TypeScript、MapLibre、ECharts；
- Parquet + DuckDB，演示阶段继续使用 SQLite；
- GitHub/GitLab CI 和 Docker；
- 5-20 GB 数据空间；
- 普通 CPU 开发机即可，LLM API 可选；
- 地图瓦片服务或离线河网 GeoJSON；
- 数据来源、许可、下载日期和字段说明清单。

## 8. 评测与验收

必须报告：

- 预警召回率、误报数和检测延迟；
- 上游候选召回率；
- 污染源 Top-1、Top-3 和 MRR；
- 传播时间误差；
- 置信度校准和失败案例；
- 数据缺失时的降级结果；
- 报告关键结论的证据或法规引用覆盖率。

数据按站点、事件或时间分组切分，禁止把同一事件的相邻记录随机分散到训练集和测试集。

## 9. 风险与处理

| 风险 | 处理方式 |
|---|---|
| 中国数据无法批量下载 | 保存获准的离线快照，记录来源；并行保留美国公开基准 |
| 缺少污染源真值 | 使用真实背景和真实河网进行隐藏真值注入 |
| 缺少高频流量 | 使用公开流量站或估算值，并降低该证据权重 |
| 缺少真实 EEM | 保留合成指纹并明确标注，后续用本地采样替换 |
| LLM 或网络不可用 | 模板降级，数值引擎和完整流程不依赖 LLM |
| 前端延期 | 优先保证地图、告警、调查时间轴和报告四个主视图 |
